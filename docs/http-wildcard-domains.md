# HTTP 隧道泛域名

HTTP 隧道的业务域名支持完整域名和开头连续的泛域名标签。配置不包含协议、端口或路径；固定后缀至少包含两个标签。忽略大小写和末尾的一个点。

| 配置 | 匹配示例 | 不匹配示例 |
| --- | --- | --- |
| `*.x.com` | `shop.x.com` | `x.com`、`a.b.x.com` |
| `*.a.b.com` | `shop.a.b.com` | `a.b.com` |
| `*.*.x.com` | `shop.dev.x.com` | `shop.x.com` |
| `*.*.*.x.com` | `shop.dev.eu.x.com` | `a.b.c.d.x.com` |

每个 `*` 仅匹配一个非空标签，最多允许三个连续的前导 `*`。固定后缀可以有更深层级；不支持 `app.*.x.com`、`foo*.x.com` 或四个 `*`。

## 匹配与转发

先匹配完整域名，再选择固定后缀最长的泛域名。例如 `shop.dev.eu.x.com` 的候选顺序为：

1. `shop.dev.eu.x.com`
2. `*.dev.eu.x.com`
3. `*.*.eu.x.com`
4. `*.*.*.x.com`

请求 Host 的端口不参与业务域名匹配。代理向目标服务保留实际请求的 Host 和 X-Forwarded-Host（包括原始大小写、端口），不会替换成配置中的泛域名，也不使用传入的 X-Forwarded-Host 选择隧道。路径、查询参数、WebSocket 和 SSE 沿用 HTTP 隧道的转发逻辑。

配置的管理地址优先于覆盖它的泛域名；内部控制和数据 WebSocket 通道仍按 NetsGo 子协议优先分流。

## 占用与冲突

- 完全相同的规范化域名规则全局唯一，同一用户也不能重复添加。
- 同一用户可以在不同客户端上添加有重叠的规则，用于精确域名或更具体的泛域名覆盖。
- 不同用户之间禁止有交集的规则。创建和修改在保存事务中检查，两个并发请求中只有一个可以取得冲突资源；失败不会修改已有配置或占用。
- 不同深度的规则不一定有交集。例如 `*.x.com` 与 `*.*.x.com`、`x.com` 都互不覆盖。
- 暂停、离线、等待启动、出错和服务重启均保留域名占用；只有成功删除或修改域名才释放相应占用。
- 已选中的更具体隧道不可用时返回 503，鉴权或来源限制拒绝时返回 401/403，代理失败时返回 502。不会继续尝试更宽的泛域名。删除更具体的规则后，同一用户的较宽规则才可能接管请求。

## DNS 与 HTTPS

需要自行将实际访问域名解析到 NetsGo 入口，并配置覆盖实际访问域名的 HTTPS 证书。本功能不创建 DNS 记录，也不扩展证书签发能力。多星号是 NetsGo 路由语法，不能直接作为多层通配证书使用；通常的 `*.x.com` 证书只覆盖一层子域名。

## 验证范围

新增测试覆盖域名语法和长度边界、具体域名集合与规则交集的一致性、优先级、不同用户隔离、事务回滚、并发占用、重启恢复、旧末尾点占用键、真实 yamux 代理、Host 保留、不可用与鉴权失败不回退、管理和内部通道优先级、WebSocket、SSE、API 创建和编辑，以及前端编辑回填。全仓库回归使用现有 CI 的 Go 测试、竞态测试、前端构建和测试及反向代理兼容测试。
